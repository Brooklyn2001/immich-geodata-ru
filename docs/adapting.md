# Адаптация проекта под свою страну и/или язык

**🇷🇺 Русский** | [🇬🇧 English](adapting_EN.md)

Это руководство для тех, кто хочет переделать проект immich-geodata-ru под свою
страну, а также, при необходимости, под другой язык локализации (не русский).

> Проект заточен под русскую локализацию 15 стран бывшего СССР. Основная ветка `main`
> остаётся русской. Для своей страны/языка рекомендуется делать **отдельный форк или
> бренч**, а не переписывать русскую версию.

---

## 1. Что меняется при добавлении страны (язык тот же, русский)

Страны **нигде не зашиты жёстко** — они заданы тремя списками и одним профилем.
Достаточно привести их в соответствие.

### 1.1 Списки стран

Все четыре места должны содержать одинаковый набор ISO-кодов страны:

1. `geodata/prepare_geoname_data.sh:16` — список для скачивания **полных данных**
   (`LIST=("RU" "BY" ... "EE")`).
2. `geodata/generate_data.sh:49` — список стран для **геокодинга** через Nominatim
   (тот же `LIST`).
3. `.github/workflows/download-geonames.yaml:26` — список стран в CI-воркфлоу
   скачивания исходников (если используется).
4. `geodata/resolver-profiles.json` → блок `countries.<CODE>` — **обязательный**
   per-country профиль (см. ниже).

> Если хотите только *добавить* страну к существующим — просто внесите её код в эти
> три списка и добавьте профиль. Если *заменить* — уберите старые коды и профили.

### 1.2 Профиль страны в `resolver-profiles.json`

Это обязательная часть. Без профиля страна не будет
геокодиться корректно: иерархия `admin_level` в OSM/Nominatim несогласована между
странами, поэтому для каждой страны задаются предпочтительные уровни для ролей
`admin_1..admin_4`.

```json
"XX": {
  "admin_levels": {
    "admin_1": [3, 4],
    "admin_2": [4, 5, 6],
    "admin_3": [6, 7, 8, 9],
    "admin_4": [8, 9, 10]
  },
  "country_code_verify": true
}
```

Как подобрать наборы: посмотреть, какие `level3..level10` реально отдаёт Nominatim
для целевой страны, и какое покрытие названий на нужном языке. Наборы проверяются
на нескольких городах. Как уровни раскладываются по ролям — см.
[patterns-granularity.md](patterns-granularity.md).

### 1.3 Прочее

- Названия стран берутся из `i18n-iso-countries` (см. раздел 2, п. «язык стран»).
- Если у страны плохое покрытие точек базовым `cities500` — может понадобиться
  `--full` (полные дампы стран), уже поддержано через `enhance_data.py`.

## 2. Что меняется при смене языка (не русский)

Русский «прошит» в несколько слоёв, поэтому смена языка затрагивает больше мест.
Общая идея: убрать русский из **всех** входов, чтобы каскад имён (см. п. 2.4)
работал на целевом языке.

### 2.1 Язык запроса к Nominatim

`geodata/generate_geodata_nominatim.py:100`:

```python
params = { ..., "accept-language": "ru,ru-RU;q=0.9,en;q=0.8" }
```

Заменить `ru` на код целевого языка (например `en,en;q=0.9` или `de,de-DE...`).
От этого зависит, какие названия вернёт геокодер на макроуровне (область/регион).

### 2.2 Приоритет языка в альтернативных именах

`geodata/utils.py:63` в `load_alternate_name`:

```python
priority = ["ru"]   # список языков по приоритету
```

Заменить на код целевого языка. Также поправить тексты логов («русских
alternateName-записей» → нейтрально), это косметика.

### 2.3 Определение «родного» слова для фолбэка

`geodata/translate.py:136-143`, функция `is_russian()`:

```python
def is_russian(text):
    ...
    for char in text:
        lowercase = char.lower()
        if not ("\u0430" <= lowercase <= "\u044f" or lowercase == "\u0451"):
            return False
    return True
```

Эта функция ищет «слово на целевом языке» среди кандидатов-имён точки как запасной
источник. Для другого языка её нужно заменить на детектор целевой письменности
(например, латиницы или специфических букв). Для языков с латиницей — проверку
на диапазон `a–z` (+ национальные буквы).

### 2.4 Язык стран (i18n-iso-countries)

Immich читает название страны **жёстко из `en.json`**, но **данные берутся из
`ru.json`** (см. `geodata/translate_country_info.py`). Не путать
источник с местом чтения:

- вместо `ru.json` источником названий стран станет JSON целевого языка
  (например `de.json`);
- `en.json` остаётся **местом**, куда Immich читает локаль — туда кладутся названия
  на целевом языке.

### 2.5 Семантика флага `--ru-pattern`

Имя флага/файлов заточено под русский (наследие исходного `--cn-pattern`). Это
косметика и менять не обязательно. Важно: **не откатывать** логику
обратно к китайским `cn`/`amap`-решениям — эта русская реализация уже переведена
на Nominatim.

## 3. Каскад имён и фолбэк — как он переключится на новый язык

Каскад в `geodata/translate.py:101-130` работает по убыванию приоритета:

1. **Из geodata** (`ru_pattern.format(...)`) — названия, уже геокодированные
   Nominatim. Станут на целевом языке после правки п. 2.1.
2. **Из alternateNamesV2** (`alternate_name[geonameid]`) — после правки п. 2.2.
3. **«Родное» слово из кандидатов** (`is_russian`) — после правки п. 2.3.
4. **Оригинал без замены** — локальное/национальное название, если нигде нет
   нужного языка.

То есть логика сама начнёт работать на целевом языке, если язык изменён во **всех
трёх** входах (2.1, 2.2, 2.3).

> **Инвариант целостности**: если точка есть в geodata, но у неё нет обязательного
> `admin_2` — строка пропускается (`translate.py:87-92`), частичный результат не
> пишется. Это сохраняется для любого языка.

## 4. Покрытие и проверка

- Для стран бывшего СССР русские названия в Nominatim есть (отличное у RU/BY,
  слабое у Прибалтики/Украины на микроуровне).
- Для страны вне региона покрытие на целевом языке в Nominatim / alternateNamesV2
  может отсутствовать — тогда **фолбэк на локальные названия** (шаг 4) будет
  срабатывать чаще. Это стоит проверить на реальных точках до полной сборки.

### Проверка

```bash
cd geodata
python -m py_compile *.py                       # синтаксис
python -m unittest discover -s tests -p "test_*.py"   # unit-тесты
```

Изменения не должны ломать пайплайн генерации и unit-тесты.
