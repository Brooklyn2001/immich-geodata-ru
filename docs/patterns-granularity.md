# Гранулярность названий: паттерны `--ru-pattern` и per-country уровни

Этот документ подробно объясняет, как проект превращает географическую точку в
название локации в Immich: что такое паттерны гранулярности (`{admin_2}` и т.п.),
как из профилей стран выбираются уровни `admin_1..admin_4`, и как это влияет на
конечные названия (включая фолбэк на локальные названия).

> Краткая версия для пользователя — в [README](../README.md).
> Принцип обратного геокодирования Immich — в [immich_reverseGeocode.md](immich_reverseGeocode.md).
> Описание пайплайна — в [geodata/README.md](../geodata/README.md).
> Как адаптировать проект под свою страну/язык — в [adapting.md](adapting.md).

## 1. Что такое «7 паттернов гранулярности»

`--ru-pattern` — параметр, который задаёт, **какие административные уровни
входят в название** и в каком порядке. Все 7 вариантов перечислены в
`release.sh`:

```bash
LIST=("{admin_2}" "{admin_3}" "{admin_4}"
      "{admin_2} {admin_3}" "{admin_2} {admin_4}" "{admin_3} {admin_4}"
      "{admin_2} {admin_3} {admin_4}")
```

То есть:

- **3 одиночных** — только один уровень: `{admin_2}`, `{admin_3}`, `{admin_4}`;
- **3 попарных** — два уровня: `{admin_2} {admin_3}`, `{admin_2} {admin_4}`, `{admin_3} {admin_4}`;
- **1 полный** — все три уровня: `{admin_2} {admin_3} {admin_4}`.

> `admin_1` в паттерн не включается никогда: это высший административный уровень
> (округ, уезд, город федерального значения), который не выводится в название.

Каждый паттерн собирается **дважды**: обычная версия (по базовому `cities500`)
и версия `--full` (с дополнением полными дампами стран через `enhance_data.py`).
Итого в архиве **14 zip-файлов** (7 паттернов × 2 варианта). Паттерн по умолчанию —
`{admin_2}` — дополнительно копируется в `geodata.zip` и `geodata_full.zip`
(см. `release.sh`).

Ровно один файл использует Immich. Выбор файла = выбор гранулярности названия.

## 2. Что такое `admin_1..admin_4`

Это административные уровни внутри страны (роли):

| Роль | Что означает |
| :--- | :--- |
| `admin_1` | высший уровень (округ, уезд, город федерального значения) |
| `admin_2` | область / регион |
| `admin_3` | район / муниципалитет |
| `admin_4` | город / населённый пункт |

Какие именно уровни попадают в каждую роль — определяется **per-country
профилями** в `resolver-profiles.json` (Вариант C), а не единым глобальным
правилом. Причина: иерархия `admin_level` в OSM/Nominatim **несогласована между
странами**, и покрытие русских названий тоже различается.

## 3. Механизм выбора уровней: `pick_admin_levels`

Код — `generate_geodata_nominatim.py:61-78`.

1. Геокодер обращается к Nominatim (`accept-language: ru`). Ответ содержит
   словарь `admin` вида `{ level3: "…", level4: "…", level6: "…", level8: "…", level10: "…" }` —
   это **сырые уровни OSM/Nominatim**, и они не обязаны идти подряд (может не быть
   level5, но быть level4 и level6).
2. Для **каждой роли** `admin_1..admin_4` функция:
   - берёт список кандидатов `profile["admin_levels"][role]` (например, для RU
     `admin_2: [4]`);
   - идёт по кандидатам в порядке набора;
   - выбирает **первый уровень, который есть в ответе и ещё не занят** предыдущей
     ролью (защита `used` от дублирования одного уровня на две роли);
   - кладёт его в `levels["admin_N"]`; если подходящего уровня нет — **пустая строка**.

То есть профиль задаёт набор «предпочтительных» уровней для каждой роли, а
алгоритм жадного выбора подхватывает ближайший доступный.

### Как читать «—»

`—` означает **пустую строку**: роль не заполнилась, потому что:

- нужного уровня не оказалось в ответе Nominatim; либо
- уровень **уже был занят** предыдущей ролью (защита `used`).

Пример — `AZ`: `admin_1: [6]` занимает l6, а `admin_2: [6]` указывает на тот же
уровень → `admin_2` пуст.

### Ключевые закономерности

- **RU — единственная страна, где все 4 слота стабильно заполнены** в обоих
  сценариях (l3/l4/l6/l8), поэтому русские названия покрыты на всех уровнях.
- **BY, UA, GE, KZ** всегда заполняют `admin_1`+`admin_2`; `admin_3` зависит от
  наличия l8/l9 в ответе.
- **Мелкие/несогласованные страны** (AM, AZ, KG, TJ, TM, MD) часто оставляют
  пустыми `admin_2` и/или `admin_3` — на этих микроуровнях и проявляется
  фолбэк на локальные названия.
- **Прибалтика (LT/LV/EE)** отдаёт роли на высоких уровнях (l5–l10): русских имён
  там на микроуровне чаще нет → местные названия.

## 5. Как паттерн превращается в название

Финальную строку собирает `translate.py` (строка `:93`):

```python
res = ru_pattern.format(**location)
```

`{admin_2}` подставляется значением соответствующей роли; пустые роли дают
пустые подстановки.

### Пример на реальных данных RU.csv

Точка: Воронежская область, городской округ Воронеж, Малоприваловское сельское поселение
(`admin_1` = Центральный федеральный округ, `admin_2` = Воронежская область,
`admin_3` = городской округ Воронеж, `admin_4` = Малоприваловское сельское поселение):

| Паттерн | Итоговое название |
| :--- | :--- |
| `{admin_2}` | Воронежская область |
| `{admin_3}` | городской округ Воронеж |
| `{admin_4}` | Малоприваловское сельское поселение |
| `{admin_2} {admin_3}` | Воронежская область городской округ Воронеж |
| `{admin_2} {admin_4}` | Воронежская область Малоприваловское сельское поселение |
| `{admin_3} {admin_4}` | городской округ Воронеж Малоприваловское сельское поселение |
| `{admin_2} {admin_3} {admin_4}` | Воронежская область городской округ Воронеж Малоприваловское сельское поселение |

У этой точки заполнены все уровни, поэтому все 7 паттернов осмысленны — разница
только в детализации: от «Воронежская область» до полной иерархии из трёх уровней.

### Пустые уровни дают «хвосты» с пробелами

Если у точки нет `admin_4` (например, «Москва» / «район Черёмушки» без уровня города),
паттерны с `{admin_4}` дают хвостовой пробел:

| Паттерн | Название |
| :--- | :--- |
| `{admin_2}` | Москва |
| `{admin_3}` | район Черёмушки |
| `{admin_4}` | *(пусто)* |
| `{admin_2} {admin_3} {admin_4}` | `Москва район Черёмушки ` *(хвостовой пробел)* |

В прод-файл (паттерн по умолчанию `{admin_2}`) такие «хвосты» не попадают.

## 6. Фолбэк на локальные названия

### Каскад выбора имени в `translate.py` (`:101-130`), по убыванию приоритета

1. **Из geodata** (уже геокодировано через Nominatim, `ru`): `ru_pattern.format(...)`.
   Если у точки нет обязательного `admin_2` — строка **пропускается** (инвариант
   целостности, `:87-92`), а не пишется частично.
2. **Русское имя из `alternateNamesV2`** (приоритет `ru`): `alternate_name[geonameid]`.
3. **Русское слово из кандидатов** (`alternatenames` в cities500): первое слово,
   состоящее только из кириллицы (`is_russian`).
4. **Оригинал без замены**: если ни на одном шаге русского нет — остаётся
   **локальное (национальное) название**.

Шаг 4 — это **осознанный инвариант из AGENTS.md**, а не баг: если русского имени
на микроуровне нет, мы не выдумываем и не заменяем, а оставляем национальное.

### Из-за чего появляется фолбэк

Русские имена в Nominatim покрывают в основном **макроуровень** (регион/область) и
города. На **микроуровне** в Прибалтике (seniūnija, linnaosa) и Украине (громада)
русских имён часто нет — там остаются местные названия.

Примеры под паттерном `{admin_2} {admin_3} {admin_4}` (по реальным профилям стран):

| Страна | Итоговое название | Почему |
| :--- | :--- | :--- |
| LV | `Vidzeme Cēsu novads Cēsu pilsēta` | на микроуровне (novads) русских нет |
| EE | `Harju maakond Tallinna linn Nõmme linnaosa` | linnaosa/seniūnija — местные |
| UA | `Вінницька область Вінницький район Агрономічне` | макро переведено, микро (громада) — локальное |
| KG | `Чүй облусу Аламүдүн району Лебединовка` | названия уровней кыргызские (облусу/району) |
| RU | `Московская область Одинцовский городской округ Одинцово` | всё русское — фолбэк не срабатывает |

### Практический вывод

Чем больше уровней в паттерне (ближе к `{admin_2} {admin_3} {admin_4}`), тем чаще
в конце названия будет национальное слово (novads, linnaosa, громада, району),
потому что русские имена есть в основном на макроуровне. Поэтому дефолтный
паттерн в Immich — `{admin_2}`: он даёт чистые русские названия регионов без
примесей локальных микроуровней.
