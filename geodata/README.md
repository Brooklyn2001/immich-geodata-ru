# Как генерируются данные

В этом проекте для генерации и обновления географических данных используются следующие скрипты и каталоги:

- `data/` — хранит результаты сопоставления координат и местоположений по странам (CSV).
- `dict.txt` — словарь названий мест, применяемый вручную.
- `enhance_data.py` — дополняет данные полными данными GeoNames (например, `RU.txt`), повышая точность.
- `generate_geodata_nominatim.py` — выполняет обратное геокодирование через **Nominatim API** по данным `cities500.txt` для нужных стран и записывает CSV-файлы в каталог `data/`.
- `prepare_geoname_data.sh` — скачивает из GeoNames свежие исходные данные (например, `cities500.txt`).
- `release.sh` — главный скрипт сборки/публикации: запускает всё и упаковывает полный набор данных.
- `translate.py` — выполняет перевод (локализацию) сгенерированных geodata-данных.
- `update.sh` — скрипт автоматического скачивания и обновления geodata; можно запускать по расписанию для автоматизации.

Чтобы сгенерировать данные, достаточно выполнить `bash release.sh`. Пример:

```bash
# Подготовка данных GeoNames
bash prepare_geoname_data.sh
# Генерация данных
# ru-pattern: управляет форматом отечественных данных, {} заменяются значениями;
#             допустимые значения admin_1,admin_2,admin_3,admin_4 — разные уровни административных единиц
# output: выходной файл
# full: использовать ли расширенные данные
bash generate_data.sh --ru-pattern "{admin_2} {admin_3}" --output "output/geodata.zip" --full
```

Если нужно добавить больше регионов, измените параметры в скриптах:

- Список стран для **расширенных** данных: измените `LIST` в файле `prepare_geoname_data.sh` (строка ~16).
- Список стран, для которых нужно геокодирование через Nominatim: измените `LIST` в файле `generate_data.sh`.

Если нужна кастомизация, читайте дальше.

## Как работает Immich

Прежде чем разбираться, как генерируются данные, нужно понять принцип обратного геокодирования Immich.

> Подробнее о принципе можно прочитать в [этой статье](../docs/immich_reverseGeocode.md).

Immich для обратного геокодирования использует следующие файлы (лежат в папке `/build/geodata`):

- `admin1CodesASCII.txt`: список административных единиц 1-го уровня (`id | name | name ascii | geoname id`)
- `admin2Codes.txt`: список административных единиц 2-го уровня (`id | name | name ascii | geoname id`)
- `cities500.txt`: список всех городов с населением свыше 500 человек
- `geodata-date.txt`: дата обновления данных
- `ne_10m_admin_0_countries.geojson`: деление стран Natural Earth, [подробнее](https://github.com/nvkelso/natural-earth-vector/tree/master)

Immich по координатам фото превращает их в **страну, регион, город** (три уровня). Процесс такой:

- по `cities500.txt` находит ближайшую точку и берёт её название как **город**;
- по полю `admin1Code` этой точки находит название **региона** в файле `admin1CodesASCII.txt`;
- по полю `countryCode` точки с помощью библиотеки [node-i18n-iso-countries](https://github.com/michaelwittig/node-i18n-iso-countries) получает название **страны**.

> Да, `admin2Name` вообще не используется, как и `admin2Codes.txt`.

Поэтому для локализации достаточно:

- заменить названия в `cities500.txt` и `admin1CodesASCII.txt` на русские;
- заменить данные в библиотеке [node-i18n-iso-countries](https://github.com/michaelwittig/node-i18n-iso-countries) на русские.

В [коде Immich](https://github.com/immich-app/immich/blob/1311189fab958bea2177a92e1cc1b7ebb1822bd8/server/src/repositories/map.repository.ts#L131) преобразование кода страны жёстко зашито в `'en'`, поэтому можно только заменить `en.json` из [node-i18n-iso-countries](https://github.com/michaelwittig/node-i18n-iso-countries) на русские данные. Полученный файл лежит [здесь](https://github.com/Brooklyn2001/immich-geodata-ru/blob/main/i18n-iso-countries/langs/en.json).

## Локализация геоданных

Исходные географические данные берутся из GeoNames, скачать их можно [здесь](https://download.geonames.org/export/dump/).

Общий процесс:

```bash
# Получить свежие данные
bash prepare_geoname_data.sh
# Усилить исходные данные (для стран из LIST, например RU/BY/UA)
python enhance_data.py
# Обратное геокодирование через Nominatim API
LIST=("RU" "BY" "UA")
for item in "${LIST[@]}"; do
    python generate_geodata_nominatim.py --country-code "$item"
done
# Локализация файлов
python translate.py
```

### Локализация admin1ASCII.txt

> `translate_admin1()` в `translate.py`

Эта часть данных относительно проста и стабильна: GeoNames предоставляет [alternateNamesV2.zip](https://download.geonames.org/export/dump/alternateNamesV2.zip), где содержатся альтернативные названия всех мест. Достаточно найти в нём русские названия соответствующих мест (поле языка `ru`) и заменить ими исходные.

Конечно, русские названия в alternateNamesV2 есть не для всех единиц, но для крупных стран данных обычно достаточно. Если у вас есть более полные данные переводов или идеи улучшения — welcome, создавайте issue или PR.

Хотя `admin2.txt` не используется, он тоже локализуется тем же способом.

### Локализация cities500.txt

> `translate_cities500()` в `translate.py`

Исходные названия в файле слишком детальные — многие дошли до уровня сельсовета, что очень неудобно для поиска. Поэтому при локализации всё приводится к трём уровням **страна, 1-й уровень, 2-й уровень**, например:

- Россия, Московская область, г. Москва
- Беларусь, Минская область, Минск
- Украина, Киевская область, Киев

Эти данные получаются при обратном геокодировании; в папке `data` сохранены данные всех точек и 4-го уровня. Если нужно изменить гранулярность — меняйте уровень данных в `translate.py`.

`cities500` — это города с населением более 500 человек, но данные по численности населения в нём не всегда точны, из-за чего Immich может определять место неточно. К счастью, GeoNames предоставляет полные данные по отдельным странам, и при необходимости их можно добавить. `enhance_data.py` умеет читать полные данные стран из `./geoname_data/extra_data` и добавлять в `cities500.txt` записи с населением больше 100 либо специфичные записи (например, для городов федерального значения), настройки можно менять в коде. Так в `cities500.txt` оказываются более детальные данные.

Далее остаётся заменить данные 2-й и 3-й колонок в `cities500.txt` по правилам:

- если для страны есть данные в папке `data` — заменить на название **2-го уровня**;
- если в alternateNamesV2 GeoNames есть русское название — заменить на него;
- если русское название найдено в 4-й колонке (альтернативные имена) — заменить на него;
- если ничего нет — оставить исходное название.
